# PM 灵感台：产品规格草案

状态：待确认。暂定名「PM 灵感台」，仓库名 `pm-copilot-agent`，品牌以后可配置替换。

一句话：面向 AI 产品经理的个人智能体，将有来源的线索变成可验证的产品点子，再生成可评审的 PRD，并记住用户明确保存的产品背景和决策。

## 用户与首版范围

用户已确认：AI 产品经理，希望找点子、写文档。具体细分领域未知，因此通过产品背景卡填写目标用户、场景、资源约束、当前产品阶段；不预设电商、金融等行业。

首版做 M1–M4 + D1 + D4：中文品牌和界面、可配置 DeepSeek、两个业务工作流、显式记忆、权限确认和审计。优先扩展上游界面；固定版本后若成本过高，才增加薄的 Python Web 界面。不得另写 Agent Loop。

### 场景一：发现产品机会

输入：目标人群、问题方向，以及用户粘贴的访谈、竞品介绍或公开链接。联网发现使用受限搜索/抓取工具；没有搜索凭证或网络失败时允许粘贴资料，不冒充联网成功。

输出 3–5 张机会卡，每张包含：用户痛点、原始来源、事实与推测、现有替代方案、AI 必要性、最小验证实验、成功指标和主要风险。评分是用于讨论的主观判断，不包装为市场数据。用户选择一张卡继续，不自动扩写所有点子。

验收：至少 2 份输入资料完成一次机会发现；每个事实性结论可追溯到来源；来源不足时明确“待验证”，不会生成伪造引文。页面可看到工具名称、状态、耗时和失败原因。

### 场景二：从机会卡生成 PRD

输入：选中的机会卡、目标用户、业务目标、约束。关键缺口以少量问题收集；缺少答案时标成假设，不自行声称用户已确认。

输出 Markdown PRD：背景与证据、目标和非目标、用户故事、功能优先级、主流程与异常流程、验收标准、指标定义、AI 能力边界、评测样例、风险与上线条件。另附待决策问题，支持逐段修改和下载。

验收：同一机会卡生成完整 PRD；每项 P0 功能至少一条可测试的验收标准；引用保留；覆盖已有版本时显示差异和确认操作，拒绝后原文件内容不变。

### 场景三：记住背景并安全修改

仅用户明确要求保存的目标用户、写作偏好和产品决策进入长期记忆。页面可查看、修改、删除记忆；会话历史与长期记忆分开展示。删除后不再把对应条目注入新会话，历史副本的清理范围须单独说明。

验收：保存“面向小团队，PRD 使用中文”，重启后新会话仍能使用；删除后新会话不再从长期记忆读取；删除或覆盖操作须确认且有审计记录。日志不保存 key 或完整敏感正文。

## 页面与操作

左侧：会话、产品背景、机会库、文档库。主区：对话和工具状态。侧栏：来源、机会卡详情、PRD 预览、待确认操作。设置页显示模型、预算和连接状态；API key 仅在本地配置，不显示原值。

## 执行边界

- 自动允许：读取指定资料目录、检索公开资料、生成新版本草稿。
- 必须确认：覆盖已有文档、删除记忆或产物；确认绑定具体参数和文件版本。
- 首版不提供：任意 shell、任意路径读写、自动安装外部 Skills、自动向他人发消息或提交文档。
- 不做多用户、微信、移动端、复杂 RAG、多个 MCP 拼装。MCP 为后续可选接口，不作为已经完成的能力。
- 后续可增加按用户指定时间生成机会简报；首版先完成主动点击触发的闭环，定时主动发现记入 IDEAS，避免超范围。

## 验证与交付

离线模拟模式必须明显标识；只验证流程，不等于模型跑通。最终交付须有真实模型对话、一次真实工具调用、重启记忆验证、安全拒绝/批准验证、截图、30 秒演示、README、来源和许可证声明、面试讲解稿。

预算默认建议 $1 / 天，支持修改；价格、次数、超时和 token 上限配置化。没有 key 时不发起付费调用。远程发布、网站卡片和群分享需要实际目标账号及明确发送授权，不能作为本地开发完成项勾选。
