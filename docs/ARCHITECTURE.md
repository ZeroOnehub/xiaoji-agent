## 分工边界

- 上游负责模型对话循环、会话机制和工具调用协议。优先使用公开 SDK 或扩展机制，业务代码不侵入上游内部实现。
- 业务扩展负责机会卡结构、PRD 模板、证据关联、显式偏好和权限策略。Skill 是任务指引，权限由执行层强制检查，不能只写在提示词里。
- 上游若存在默认自动记忆、shell 或宽松文件工具，应用配置须关闭或替换。不能在 UI 隐藏按钮后声称后端已受限。
- 固定上游 tag/commit 与依赖锁定信息；保留许可证和修改说明。应用目录与 agent 数据目录隔离。

## 数据模型

- ProductProfile：目标用户、产品阶段、业务约束、明确确认的偏好。
- Source：URL 或本地文件 ID、获取时间、内容摘要、抓取状态。
- Opportunity：痛点、来源 ID、假设、验证实验、评分理由。
- Document：关联机会 ID、版本、内容路径、摘要、更新时间。
- Memory：内容、来源会话、用户授权时间、删除状态。
- Approval：操作、参数摘要、目标版本、过期时间、状态。
- AuditEvent：工具名、开始/结束时间、审批 ID、结果、脱敏错误。

结构化业务数据建议 SQLite；导出文档使用 Markdown。上游会话存储先复用，不自行再造一套聊天数据库。具体记忆落点在基线验证后确定，保持单一事实来源。

## 权限与并发

批准状态机：pending → approved / rejected / expired；只有 approved 可进入 executing → succeeded / failed。审批与执行结果持久化，通过事务防止重复批准触发多次执行。确认前核验文件版本，发生变化时重新请求确认。

文件路径必须解析并验证仍在资料/产物根目录，处理 `..` 与符号链接逃逸；覆盖使用临时文件和原子替换。只读资料与可写输出分开。

网页内容一律作为不可信资料；抓取限制协议、响应大小、超时、重定向，阻止私网和本地地址。输出 Markdown/HTML 渲染要防注入。服务默认仅监听本机；写接口要求会话认证及来源校验。

## 失败与费用

模型超时或限流只做有限重试，拒绝无限循环。工具失败如实返回，允许用户补资料。写入工具的结果不明时不得自动重放。任务最多 6 次模型请求；每次请求前预留最大估算费用，响应后按实际 usage 结算。并发额度预留必须使用事务，进程重启后不能清零当日支出。

## 必须实测的风险

上游版本的 SDK 可扩展性、DeepSeek 工具调用兼容性、默认记忆是否可关闭、审批是否能覆盖所有写路径、UI 事件如何暴露。任一项不满足先调整适配方案，再决定 UI 实现，不凭 README 假设接口存在。

## 实现更新

本轮实际复用 AgentLoop 与 Nanobot SDK，采用 FastAPI + 原生 JS 工作台；业务记录存 SQLite。上游运行实例为每任务临时目录，ephemeral 会话避免自动长期记忆。只注册 read_context/search_github，模型没有写入工具。审批操作直接对 SQLite 记录执行，不接受文件路径，因此草案中的磁盘写入与路径沙箱不是当前实现路径。原始/拟替换内容同时展示，尚无逐行 diff 和历史版本回滚。真实接口验证状态见验收记录.md。
