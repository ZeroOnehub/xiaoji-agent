# 实际源码借鉴与适配记录

2026-10-19 下载 HKUDS/nanobot 官方仓库，固定提交 `dca49c258a9d7efb1475dd79c7a3fd2e5b746bd2`。阅读并安装源码包，不是只引用 README。依赖通过 requirements.lock 固定；本项目没有拷贝重写 Agent Loop。

| 上游文件 | 实际作用 | 本项目如何使用 |
|---|---|---|
| `nanobot/agent/loop.py` | AgentLoop、工具注册、回合调度 | 显式实例化循环，最多 6 次模型调用 |
| `nanobot/nanobot.py` | Nanobot 高层 SDK | 使用 `stream(..., ephemeral=True)` 获取工具事件和结果 |
| `nanobot/agent/tools/base.py` | Tool 接口、参数验证 | 实现 ContextTool、GithubTool |
| `nanobot/agent/tools/registry.py` | 工具白名单 | 注销全部默认工具，仅注册两个只读工具 |
| `nanobot/providers/base.py` | LLMProvider、LLMResponse、ToolCallRequest | 自定义预算适配器与明确标识的离线演示适配器 |
| `nanobot/config/loader.py` | 运行时路径选择 | 配置路径绑定到本次临时运行目录，避免使用用户 `~/.nanobot` |
| `nanobot/session/location.py` | 会话目录与工作区分离要求 | 临时根目录保存 config/session，子目录 agent 保存工作区 |
| `docs/python-sdk.md` | SDK 用法 | 按异步上下文关闭资源，处理工具和完成事件 |

实测中遇到并解决两处真实集成差异：LLMProvider 构造要求 `provider_name`；会话存储不能位于 agent workspace 内。两项均由实际执行定位，已修正并由集成测试覆盖。

## 为什么单独做界面

当前上游已有 WebUI，且完整 UI 源码构建涉及 Bun/Node。本机没有 node 命令。为保持范围与可控工具边界，使用 FastAPI + 原生 HTML/CSS/JS 做薄工作台，上游通过 Python SDK 运行。安装跳过上游 WebUI 构建，不声称自研了上游已有的通用能力。

## 差异化贡献

- 面向 AI 产品经理的机会发现和 PRD 工作流。
- 显式授权的记忆与资料管理，而非自动收集全部对话。
- 模型无写入工具；应用端审批绑定目标版本、有效期和事务。
- 请求前原子预留费用；测试覆盖并发超预算。

## 证据边界

已跑通真实 nanobot 的工具循环，模型由演示适配器替代。DeepSeek 适配器测试使用模拟响应；不等于实际供应商验收。仍需 key 完成真实对话、真实工具选择、输出质量和成本核对。GitHub 搜索工具已实际联网检索官方 nanobot 仓库成功；真实模型自主选择该工具仍未验收。
